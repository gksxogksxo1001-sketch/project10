Analysis of Developer Divided Attention and Interaction Behaviors during Execution Latency in AI Agent-Assisted Web Programming: A Case Study on 'Honbab-Biseo' Web Service

【요 약】

최근 대규모 언어 모델(LLM)을 탑재한 자율형 AI 에이전트(Google Antigravity, Gemini 등)가 소프트웨어 개발 전반에 도입되면서, 개발자의 역할은 단순 코드 작성자에서 에이전트의 제안을 검토하고 다중 선택지(Interactive Modals)를 승인하는 '지휘·감독자'로 재편되고 있다. 그러나 에이전트가 복합 코드를 추론하고 도구를 조작하는 동안 필연적으로 발생하는 10~60초 대의 유휴 대기 시간(Execution Latency)은 작업자의 집중 흐름을 분산시키는 새로운 인지적 도전을 유발한다. 본 연구는 자취생 냉장고·식비 관리 웹서비스인 '혼밥비서(Honbab-Biseo)'의 프론트엔드(HTML/CSS/JavaScript 및 식약처 Open API 연동)를 구현한 개발자 1인을 대상으로 7일간 총 36회의 실측 세션을 수집하여, 에이전트 대기 시간 동안 나타나는 인지적 주의 분할(Divided Attention), 브라우저 검수 행동, 그리고 에이전트 다중 선택지 결정 패턴을 실증적으로 분석하였다.

실측 결과, 에이전트 대기 시간이 16초를 초과할 때 작업자는 외부 미디어로 완전 이탈하기보다는 F12 개발자 도구 콘솔 점검 및 모바일 뷰포트 반응형 UI 검수(61.5%)를 수행하는 '비동기적 자체 검수 행동'을 보였으며, 에이전트의 중간 확인 모달을 놓치지 않기 위해 평균 12.7초 간격으로 IDE 창을 힐끔 확인하는 '시각적 폴링(Visual Polling)'을 91.7%의 높은 비율로 유지하였다. 또한 에이전트가 제시한 3가지 해결 옵션 중 78.3%의 확률로 '중간(2번째) 옵션'을 채택하고 장문 설명을 기피하는 인지적 피로 회피 편향이 관측되었다. 본 논문은 실제 현업 웹 개발의 구체적 로그와 디버깅 에피소드를 바탕으로 에이전트 협업의 실효적 인지 비용을 정립하고, AI 도구의 피드백 설계 가이드라인을 제언한다.

주제어: AI 코딩 에이전트, 구글 안티그래비티, 혼밥비서, 분할 주의(Divided Attention), 시각적 폴링(Visual Polling), 다중 선택지 편향, 단일 피험자 실증 연구(N=1)
【Abstract】

With the rapid adoption of LLM-based autonomous agent tools (e.g., Google Antigravity, Gemini), software developers increasingly function as supervisors who evaluate generated code and approve interactive options. However, agent execution latencies (10–60 seconds) impose novel cognitive demands. This empirical single-subject (N=1) study investigates a front-end developer engineering the 'Honbab-Biseo' web service (vanilla HTML/CSS/JavaScript and public OpenAPI integration) across 36 sessions over 7 days. Findings reveal that during latencies exceeding 16 seconds, the developer rarely exhibits complete disengagement; rather, the developer actively engages in asynchronous validation tasks—inspecting DevTools console outputs and testing mobile responsive breakpoints (61.5%)—while sustaining periodic 'visual polling' every 12.7 seconds (observed in 91.7% of off-IDE sessions) to handle confirmation modals. Furthermore, a pronounced middle-option selection bias (78.3%) and text-fatigue evasion were identified in multi-option decision contexts. We quantitatively detail developer behavior under agentic workflows and provide actionable interaction guidelines for AI-assisted software engineering.

1. 서 론

현대 웹 프론트엔드 개발은 복잡한 반응형 레이아웃(CSS), 동적 DOM 조작 및 외부 공공데이터 API 비동기 처리(JavaScript)가 결합되어 디버깅과 검수에 막대한 인지적 노력을 요구한다. 최근 등장한 자율형 AI 에이전트(Google Antigravity, Gemini 등)는 자연어 지시만으로 파일 시스템을 직접 탐색하고 코드를 수정·반영하는 기능을 제공함으로써 개발 주기를 혁신적으로 단축하고 있다.

그러나 자율 에이전트는 개발자의 지시를 받아 스스로 터미널을 열고 코드를 패치하는 동안 수십 초에 달하는 '추론 및 실행 대기 시간(Execution Latency)'을 발생시킨다. 이 시간 동안 개발자는 가만히 화면을 응시하기보다 다른 창으로 이동하거나 모바일 알림을 확인하지만, 에이전트가 불시에 "다음 단계로 진행해도 될까요?" 또는 "3가지 옵션 중 하나를 선택해 주세요"라는 인터랙티브 모달을 띄우기 때문에 완전히 몰입을 전환하지 못하는 '주의 분할(Divided Attention)'과 지속적 긴장 상태에 놓이게 된다.

본 연구자는 실제 3인 팀 프로젝트로 자취생을 위한 스마트 냉장고·레시피 관리 웹서비스인 '혼밥비서(Honbab-Biseo)'의 프론트엔드 코어(식재료 유통기한 계산, 식약처 공공 API 연동, 반응형 UI 모달 등)를 개발하면서, 이러한 에이전트와의 협업 과정에서 발생하는 주의 분산과 인지적 스트레스를 체감하였다.

이에 본 연구는 주관적인 느낌을 배제하고, 실제 개발 세션에서 발생한 초 단위 대기 시간 로그, F12 개발자 도구 및 모바일 뷰 검수 행동, 그리고 에이전트의 3지 선다 모달 응답 패턴을 실측하여 **"에이전트 대기 시간이 인간 개발자의 주의 분할 및 상호작용 의사결정에 미치는 구체적 영향"**을 규명하고자 한다.

핵심 연구 가설:
"AI 에이전트의 실행 지연 시간이 길어질수록, 작업자는 외부 오락물로 이탈하기보다 개발 화면의 비동기적 UI/콘솔 검수로 주의를 분할하며, 에이전트의 선택지 요구에 응답하기 위해 10~15초 주기의 시각적 감시(Visual Polling)를 지속한다."

3. 연구 대상 프로젝트 및 실험 설계

3.1 대상 프로젝트 ('혼밥비서'):
연구 대상 과업은 자취생을 위한 스마트 냉장고·레시피·식비 관리 웹서비스인 '혼밥비서'이다. 본 피험자는 3인 팀 중 프론트엔드 핵심 모듈을 전담하였으며, 주요 구현 파트는 다음과 같다:

  • 냉장고 식재료 관리: 식재료 유통기한 D-day 임박도 계산 알고리즘, 신선도 상태별 뱃지 표기, 재료 등록/수정/삭제 모달 인터랙션.
  • 식약처 공공 API 연동: 식품의약품안전처 식품영양성분DB 오픈 API를 비동기 호출하여 5대 영양소(칼로리, 탄수화물, 단백질, 지방, 나트륨) 실시간 파싱.
  • 반응형 UI/UX: 모바일 뷰포트(375px~430px)와 데스크톱 뷰포트 간의 CSS 미디어 쿼리 레이아웃 검수.

3.2 에이전트 상호작용 및 프롬프트 파이프라인:
피험자는 에러 발생 시 곧바로 AI에 의존하지 않고, 약 10분간 브라우저 F12 개발자 도구 및 배포 내역을 스스로 디버깅한 후 한계에 봉착했을 때 에이전트를 호출하였다. 프롬프트 작성 시에는 "이러이러하게 만들고 싶고, 가시성을 확보하며 UI/UX 흐름을 이렇게 연결해 줘"라는 요구사항과 함께 화면 에러 캡처 스크린샷을 동봉하여 3~5줄 분량의 구조화된 프롬프트를 전달하였다.

3.3 변수 정의 및 측정 지표:

  • 독립변수 (에이전트 실행 대기 시간, 초): 사용자 프롬프트 전송 후 에이전트가 파일 수정 및 도구 실행을 마치거나, 중간 선택 모달을 띄우기까지의 시간.
  • 종속변수 1 (작업자 행동 유형): ① IDE 화면 지속 주시, ② 혼밥비서 웹사이트 UI/콘솔 검수, ③ 모바일 알림 확인.
  • 종속변수 2 (시각적 폴링 간격, 초): 타 창을 보면서도 에이전트의 진행 상태 및 선택 모달을 확인하기 위해 IDE로 시선을 되돌린 주기.
  • 종속변수 3 (모달 옵션 선택 위치): 에이전트가 제시한 3가지 해결 방안 중 몇 번째 옵션을 선택했는지의 여부 (1번, 2번, 3번).

4.1 비동기적 사이트 검수 행동의 지배성:
대기 시간이 16초 이상으로 넘어가면, 작업자는 54.5%~66.7%의 높은 비율로 개발 중인 혼밥비서 웹 화면(로컬호스트/배포 사이트)으로 이동하였다. 주된 행동은 "F12 키를 눌러 개발자 도구 콘솔에 빨간색 에러 로그가 남아있는지 확인"하거나, "크롬 개발자 도구의 디바이스 툴바를 켜고 모바일 환경에서 유통기한 D-day 뱃지와 모달 UI가 깨지는지 검수"하는 실무적 점검이었다.

4.2 시각적 폴링(Visual Polling)과 분할 주의 비용:
에이전트 구동 중 타 창으로 이동한 24개 세션 중 91.7%(22회)에서 10~15초(평균 12.7초) 주기로 IDE 창을 힐끔 쳐다보는 행동이 기록되었다. 피험자 심층 인터뷰 결과, 이는 에이전트가 언제 선택지를 띄우고 멈출지 예측할 수 없기 때문에 발생한 필연적 경계 감시(Vigilance Cost)로 확인되었다.

4.3 3지 선다 모달에서의 '중간(2번째) 옵션 선호' 편향:
에이전트가 3가지 해결책을 제시한 세션(총 23회)을 분석한 결과, **23회 중 18회(78.3%)에서 피험자는 2번째 옵션을 선택**하였다. 1번째 옵션은 과도하게 단순하거나 기존 구조를 급변시키고, 3번째 옵션은 설명 텍스트가 너무 길어 인지적 과부하를 유발했기 때문에, "설명이 적당히 정돈된 중간 타협안"을 직관적으로 클릭한 것으로 분석되었다. 특히 설명이 너무 긴 옵션은 아예 읽지 않고 스킵하는 현상이 관찰되었다.

4.4 에이전트 연속 실패 시 인지적 스트레스 급증:
10분간의 자체 디버깅 후 답답한 심정으로 에이전트에 스크린샷을 올렸으나, 에이전트 역시 해결하지 못하고 연속으로 오류를 낼 때 피험자는 극심한 피로와 몰입 저하(멘탈 소진)를 경험했다고 진술하였다.

4.5 가설 검증 판단 및 가설 수정 전·후 비교 (T10-C32 ~ C37):
  • 가설대로 나온 부분 (지지): 대기 시간이 16초 이상 증가함에 따라 IDE 이탈률이 급증(0~15초 20.0% ➔ 31초+ 93.3%)한다는 점은 원자료 수치로 명확히 입증됨.
  • 가설과 다르게 나온 부분 (기각 및 수정): 당초 가설은 작업자가 유튜브나 웹서핑 등 '완전한 유희적 딴짓'으로 이탈할 것으로 예측했으나, 실제 원자료에서는 **이탈 세션 24회 중 18회(75.0%)가 F12 콘솔 에러 점검 및 모바일 반응형 뷰포트 검수라는 업무 연장선상의 보조 행동**으로 나타남.
  • 다르게 나온 이유로 검토한 3가지 가능성: ① 프로젝트 마감 압박감에 따른 자발적 몰입 유지, ② 언제 뜰지 모르는 에이전트 확인 모달에 대한 경계 심리, ③ 브라우저와 IDE 간의 손쉬운 Alt+Tab 접근성.
  • 가설 고치기 전: "에이전트 대기 시간이 길어지면 작업자는 비업무적 외부 미디어로 완전 이탈할 것이다."
  • 가설 고친 후 (최종): "에이전트 대기 시간이 길어지면 작업자는 외부 오락물 대신 비동기적 사이트 자체 검수로 주의를 분할하며, 모달 응답을 위해 10~15초 주기의 시각적 감시(Visual Polling)를 지속한다."

5. 결론 및 실무적 제언

5.1 학술적 의의 및 결론:
본 연구는 실제 웹 프로젝트('혼밥비서') 프론트엔드 개발 과정을 단일 피험자(N=1) 실측 기법으로 추적하여, AI 에이전트의 대기 시간이 유발하는 상호작용의 실체를 밝혔다. 에이전트 대기 시간은 단순한 유휴 시간이 아니라, **'F12 콘솔 및 모바일 뷰 검수'라는 보조 업무와 'IDE 시각적 감시'가 교차하는 복합적 분할 주의 영역**임이 실증되었다.

5.2 AI 도구 설계 및 개발자를 위한 제언:
1) 청각/푸시 피드백 도입: 에이전트가 중간 선택 모달을 띄울 때 시각적 주시를 강요하지 않도록 명확한 비프음이나 OS 알림을 제공해야 한다.
2) 모달 옵션 텍스트 간소화: 작업자는 긴 설명을 기피하고 2번째 옵션에 편향되므로, 옵션당 핵심 차이점 1줄과 위험도만 간결히 요약 제시해야 한다.
3) 에러 캡처 자동 분석 파이프라인: 스크린샷과 콘솔 로그를 원클릭으로 결합하여 에이전트의 1회차 성공률을 높여야 한다.

【단일 피험자(N=1) 연구의 한계 명시】:
본 연구는 '혼밥비서' 프로젝트를 전담한 단일 프론트엔드 개발자 1인의 작업 로그에 기반하므로, 백엔드 대규모 분산 시스템이나 다인 페어 프로그래밍 환경으로 즉각 일반화하기에는 한계가 있다. 그러나 가상의 설문 조사가 주는 허위·회상 왜곡을 배제하고, 실제 개발 현장의 생생한 36회 세션과 구체적 에러 극복 과정을 정직하게 실측했다는 점에서 높은 현장 적합성을 지닌다.
